# 《记忆余量》与《旧街最后一封信》体验差异审计

日期：2026-09-20
对照范围：旧街正式探索壳 `old-street-dev.tsx` 及其地图、对话、人物移动、背包、菜单、音频、结局组件；《记忆余量》当前真实运行入口、权威状态、浏览器存储与发布构建。

## 审计方法

这次不再按用户逐条举例补功能。对照按玩家实际经历的顺序分为：首次进入、探索移动、人物行为、交谈、调查资料、地图/背包/菜单、声画反馈、存档恢复、章节收束。每一项同时检查源码合同、真实 UI 状态和可自动验证的行为。

状态定义：

- **一致**：题材内容可以不同，但玩家获得的功能和反馈层级相同。
- **已复验**：本轮修复已在 390×844 与 320×568 的真实浏览器连续路径中通过。
- **部分一致**：已有基础能力，但少了原作中会影响体验的层级。
- **缺失**：新版没有对应能力。
- **题材差异**：属于旧街章节内容，不应硬复制到新故事。

## 根因

上一版技能把“空间结构正确”当成了“体验接近原作”。它对墙地、门、碰撞、比例、资料和发布写得较细，但参考完整性只列了地图、背包、菜单与可持续交谈，没有把以下内容设为阻断项：

1. 新旅程必须经过剧情处境与首个动作引导；
2. 物理 NPC 必须有环境活动、注意范围、面向玩家和与动态位置一致的碰撞/接近点；
3. 对话必须按时间顺序展示，而不是只保证信息存在；
4. 声音、存档层级、结局演出和对话历史必须逐项声明是否达到参考层级。

因此，自动化能证明“按钮存在、路线能走、话题数量够”，却不能证明新版拥有原作的生活感与叙事引导。这是技能验收模型的缺口，不是单个 CSS 问题。

## 本轮收口顺序

1. 已完成开场、NPC 环境行为、分阶段对话的真实浏览器复验；
2. 已把上述四项写入技能参考完整性合同与验收矩阵；
3. 背包图像识别、等待状态区分、脚步层和结局演出保留为后续 P1，不能冒充本轮已达参考层级；
4. 重新打包并让独立验证器检查技能是否能在不打开原作仓库的情况下发现这些缺口。

## 技能级能力判定

本项目现在使用 `doc/experience-capabilities.json` 明确声明产品画像和能力状态。当前发布目标如实标记为 `playable`：开场、探索、NPC 生活、分阶段对话、恢复和章节结果已实现；对话历史、背包图像识别和距离脚步仍为 `planned`。把目标提升为 `high-fidelity` 时，新校验器会阻断这三个缺口，避免接收方仅凭“游戏能通关”把它们静默省略。

单旅程、本地 session 恢复和作者对白是本作明确选择，不再被一概视为低质量；若未来画像要求分支比较、多人共用设备、跨设备继续或生成对白，校验器会条件触发多旅程、账号云存档和生成边界/回退能力。
