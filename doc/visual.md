# 《记忆余量》视觉方向与界面系统

## 视觉命题

玩家刚把意识上传，第一次在数字世界的居所醒来。这个世界应先像真实的生活空间：杯子、旧衣、门牌、邻居留下的纸条都有具体位置；只有在记忆断裂或所有权被触碰时，设施的冷光才显露出来。玩家记住的第一幅画面，是一段熟悉语音播到最后突然空白，桌上物件仍然完好。温柔的表面与消失的私人记忆形成第一层不安。

用户已从六套并列评审中选择编号五 `05-terminal`“夜间终端”。界面使用深绿单色检索屏、高对比行列、指令式标题与虚线来源关系；地图继续使用正交俯视，人物与物件保持统一像素采样。终端语法只用于 HUD、短标签、按钮、编号和面板结构，长对白、说明、结局叙事与资料正文切回清晰的系统无衬线字体。

## 空间、镜头与材质

- 首轮三个有用途的地点：转生居所（私人记忆）、公共走廊（邻里行动）、记忆服务点（制度留下的记录）。地板、直墙、墙角、墙脚、门洞、门和家具分别由平台媒体服务生成独立素材，在场景数据中按世界坐标拼装；同一实例同时决定画面、碰撞与交互。已生成的整张房间图仅保留为候选构图参考，不进入最终运行背景。
- 手机镜头沿用旧街的探索景别思路：地图铺满 HUD 之间的可用区域，轻度推进并随人物脚点移动，不再把完整 384×512 世界缩成居中的总览卡片。当前镜头在 320–390 宽度间等比放大 1.05–1.22 倍；短屏保留开场桌面目标，长屏让房间接近满高。镜头只裁切视口，不改变人物、物件、碰撞、接近点或存档中的世界坐标。
- 可探索空间固定沿用《最后一封信》已认可的 B 式正交俯视：能看到人物头顶与物件顶面及短立面，平行线不收敛，画面上方的同类物件不缩小。背景、门、家具、可拾物、人物站姿与四向动作都以这组实际运行资产为共同参考，并核对地砖、门宽、人高、脚底及光向。旧主角的黄衣和身材不是新主角模板。人物以脚底定位，桌、柜、人物遮挡依据落地深度；墙面为不会变化的背景，语音盒、回执、门、服务窗口和人物是独立状态物件。
- 地图人物统一用 256×256 源格和 y=233 脚点，显示格 60×60 世界单位；主角与三名成人 NPC 的可见高度约 45–47。旧街已认可主角的运行值约 32–34，这个房间的桌、门、地砖密度不同，比例以新场景同屏验收为准。四张桌子的可见宽度约为主角身高的 1.01–1.10 倍，缩小的视觉足迹与碰撞、接近点一并检查。两种桌面都保持前后边等长、左右边平行；桌上小物件按正方形单格等比显示，以可见底部接触点落在桌面上表面为准，不随矩形热点拉伸。每张生成结果先量 alpha 主体，而不是直接把各自的画布缩放到同一 CSS 方框。主角是 P0 美术资产：四方向三帧必须逐格记录平台 request/task/SHA，运动帧必须是完整身体，禁止反射或复制局部腿部；完整右向可以由完整左向镜像。脚底、头部和高度机械稳定后，还要在真实地图连续查看左右/上下动画。当前 v7 已通过机械门禁和真实 renderer 的四方向连续帧验收。
- 北墙的 768×256 源图按世界宽等比裁切到 276×64 的墙面，墙脚外加短阴影；居所、走廊、服务点各自使用 256×1536 的连续侧墙素材，按完整外墙高度等比定位，门洞只做裁切，右侧只做整图镜像。侧墙不得由短段反复拉伸，也不得用通用米色窄条套全部场景。顶部侧墙盖住北墙两端；底部南墙的墙帽、立面与墙脚向左右外伸一个侧墙厚度，盖住侧墙端头。真实门洞处才中断墙面。南墙使用等比裁切。源图裁切处的面板、纹理和端面仍需在逐场截图中复验，不能因为计算比例通过就判断整体高保真。
- 门分为两套方向结构。北门与南门使用同一平台生成的直立开门图集，保持正面朝向，不旋转；北门位于人物后，南门随前景墙显示。东西侧门由方向专用的短过门石、远端墙截面、近端前景墙截面和独立侧门板组成。当前过门石源图的长轴已经沿侧墙方向，运行时不得再次旋转；直立门板也不旋转。门板素材只能包含可移动木门扇及自身薄边，不能再带固定门框、门楣、门槛或墙面，否则打开后会像第二个门洞漂在地面上。门板朝当前房间打开时显示完整正面并按人物脚点切换遮挡层，朝相邻房间打开时只显示门槛。墙洞、门槛站位、接近点、脚点激活区和转场到达点来自同一扇门记录，站在门槛及刚抵达时都能立即操作。
- 剧情特写例外：资料放大、人物肖像、关键物件近景和过场可以采用正面、侧面或局部镜头；它们只用于阅读/特写界面，不能充当地图内可行走的场景物件。物件身份、材质和状态仍与地图版本一致。
- 纹理靠清楚的边缘、磨损和少量噪点表达生活痕迹。数字材质只在接口、记忆槽和登记屏上出现，避免整场景镜面金属或高亮霓虹。
- 服务点的近未来感由功能分区和设备基础设施承担。左侧记忆接入工位由晶片缓冲柜、主终端和朝向终端的接入椅组成；右侧处理 / 检修工位由主终端和维护台组成；中央保持通道。主终端、柜体与维护台统一深石墨、旧黄铜和青色记忆波形 / 晶片槽，接入椅保留接触导轨、状态节点与短光纤。家具不能只因单件正投合格就平均散放，组合后必须能回答“谁坐在哪里、设备怎样连接、工作人员在哪里维护”。
- 白盒先验证两次往返、通行净宽和手机视口。最终视觉与音频资产统一经 AlterU 平台媒体服务生成，保留公开参考 URL、提示词、请求 ID、结果 URL、实际尺寸、SHA256 和准入状态；当前非平台产出的诊断图不得作为最终资产。不能仅凭单张图好看就替换已准入素材。

## 核心画面与信息层级

- **新旅程开场**：用覆盖在真实居所之上的终端式短面板呈现三段玩家当下经历，下面单独强调“先走近语音盒，再按右下行动键”。开场不列派系、价格或完整制度，也不展示碰撞、存档等内部信息；开始探索后面板完全离场。
- **探索**：地图占主体，目标只写眼前动作，如“听完那段语音”。地图热点只负责寻路；靠近后底部单一行动按钮显示目标名与动词，按钮状态使用稳定焦点和距离迟滞，不能在相邻物件之间闪烁。按按钮后才在地图上方展开局部内容层，不用全屏暗幕切断空间感；移动、点击空地、关闭或再次按按钮退出。提示和面板不能改变地图尺寸或挤动镜头。
- **首次缺页**：播放器先展示可理解的前半段，再发生可见/可听的短缺口。静音时仍有空白波形和“不完整”的文字，不能依赖声音独占线索。
- **资料阅读**：物件上的资料可以只读放大，清楚显示来源、时间与已知/未知字段；关闭后保持外层滚动、当前选择与人物位置。资料放大本身不提交结论。
- **人物与对话**：首次登场先看见外形和动作，再获得称呼。邻居在安全范围巡游，值守人短距离巡逻，窗口职员守位；接近或选中后停止并面向玩家。首次剧情行动结束后仍保留至少两个常驻话题，并随真实调查进度增加状态话题；自由输入在同一对话流中显示玩家发言与人物回应。具体话题开始后，人物特写和初次介绍离场，让首屏依次只聚焦玩家发言、等待回应、NPC 回应，阅读停顿后才出现下一轮实底选择；长回复显式分页。善意和恶意从说法与可回访行为之间的关系显现；人物面板不提前透露本性，也不因一次性行动耗尽而失去交谈入口。
- **选择与后果**：在触及记忆使用权前，把保留、借出、可撤回性等本次真实条款并列写清；确认后回到地图看到至少一处状态变化。不可用抽象结算卡替代后果。
- **更长的世界观段落**：早餐便条先让玩家触碰转生后的感官生活，走廊告示展示别人的一格记忆难题，窗口说明牌才说出正式留存与借出规则。这三处可跳过，不在开场叠成术语页。
- **六秒预览**：第二段用邻居的无意哼唱、窗口可放大的播放记录与职员解释建立矛盾。关掉预览后，屏幕从青色条纹变暗并加斜线；追查账户后保留一小格琥珀色记录标记。两者都有明确文字状态和不同回访对白，不能只靠颜色区分。
- **地图、背包与菜单**：顶部三个入口保持稳定职责。地图使用和真实门连接相同的三节点拓扑，显示当前位置、已发现地点、选中目的地、下一道门方向与多段路线；选择地点不传送。背包含目标、物品、线索、人物四页，线索继续进入资料放大，人物只在可见介绍后出现。菜单分游戏与存档，承载声音、操作方法、当前存档和重开确认。未到过的地点不提前列出世界观术语。

## 界面几何与图标

面板和普通功能按钮全部直角；主弹层和资料查看器使用 2px 绿色外框，普通分区使用 1px 线，来源、时间线与证据关系使用虚线。触屏摇杆是直接操控例外：使用圆形轨道、四向短刻度和可偏移圆形把手，使其与普通按钮有明确区别。主要按钮至少 44×44 CSS px，文字和图标同时表达作用。亮绿只用于当前主要操作、选中和焦点，不把大面积地图或正文做成持续发光屏。统一线性 SVG 图标体系，不用 Emoji、拟物发光圆按钮或透明玻璃大卡片。必要的状态区别同时用颜色、文字和结构表达。

## 动效和声音

常规靠近 120–180ms，读取确认 180–220ms；首次缺页用一次约 400ms 的静止、波形空位和平台生成的短裂隙音效，不做频闪或持续扫描线。平台生成的 60 秒低动态环境音乐在首次操作后循环，音量低于交互提示；统一静音按钮同时控制音乐、裂隙音效和合成提示，并位于右上角工具区，不与底部移动和互动动作并列。底部主按钮在附近没有目标时保持透明空心；进入可执行距离后整块切为高对比亮绿实底，不能只改变透明度。摇杆与行动按钮在 390px 宽视口保留 16px 间隔，在 320px 宽视口保留 14px 间隔；行动文字右对齐，避免左手操作摇杆时遮住关键信息。选择后的局部设施变化可以用 400–600ms 完成。尊重 `prefers-reduced-motion`：取消位移和闪动，保留文字、颜色和物件状态。静音时缺页仍然可辨。

## 目标尺寸与验收

以平台内 390×844 为主，320×568 为窄屏复验。地图等比呈现，HUD、持续对话、真实路线图、背包、菜单、资料阅读器和选择面板各自重排；不能只把整页缩小。另测英文长句、首次进场、一个人物初见、一次性行动后重开对话、状态话题、自由输入、放大资料、选择前条款、选择后回访与错误恢复。外部访客栏仅作覆盖可用性检查，不决定平台内构图。

## 氛围密度方案（已选择）

默认入口采用平台生成的独立家具与独立使用痕迹。居所放置睡眠榻、收纳柜、维修车和拖鞋；同一放置记录同时提供显示矩形与实体家具碰撞，小件痕迹不阻挡移动。用途不同的记忆服务点使用轴向斜俯视正投的档案柜、职员低柜，并复用平台图集右下格的 45° 斜视正投单人沙发作为候位家具；正面说明牌固定在北墙。中部通道、全部剧情实体接近点与出口保持畅通。两处场景均在 390×844 与 320×568 真实 renderer 检查。

`?atmosphere=baseline` 保留空场景对照，`?atmosphere=ground` 保留完整场景图实验。后者因单件家具的投影、比例、碰撞和状态难以独立修正而未被选为默认方案。斜向本身不是拒绝理由：允许无消失点、平行边稳定、相机俯角一致的 45° 斜视正投；照片透视、正面商品图、灰底伪字和混合相机高度仍拒绝。独立放置、图集逐格准入、支撑面、碰撞、第二场景复验和最终两轮画面签收已写入共享 `build-spatial-story-game` 技能。

## 禁止漂移

禁止把旧街地图、黄雨衣、旧资料和旧结局换名复用；禁止将原“求救信号改道”占位故事接入本题材；禁止一进场出现容量、配额、机构、派系的术语清单；禁止将每个像素物件叠霓虹描边；禁止用随机谎言冒充人物复杂性；禁止用美术画出的门与实际引擎出口不一致。

## 当前状态

这是基于用户已选第五套 `05-terminal` 风格完成的独立题材首章。根节点显式记录稳定主题 ID；运行样式按技能主题目录映射探索 HUD、行动区、持续对话、真实路线图、背包、菜单与资料放大。居所、走廊与服务点使用平台生成的独立地面、北墙、场景专用连续侧墙、方向门、家具、人物与小物件；门洞由布局切墙，三处可在真实 renderer 往返。当前素材的结果、拒绝原因与来源哈希见 [art-admission.md](art-admission.md)。主角 v5 的局部腿部反射和旧通用侧墙已撤回；v7 完整身体图集与三张场景侧墙已进入真实运行截图并准入。三名 NPC 的 v6 完整身体方向图集已通过真实巡游与面向玩家画面签收。390×844、320×568 的浏览器实机视口已通过新旅程开场、NPC 巡游/注意面向、分阶段对话、地图、背包、菜单和重复交谈路径；实体手机仍未单独验证。

另有一个非正式剧情的 768×768“记忆交换大厅”大场景试验，使用同一人物与家具世界尺度，通过五个功能区、交叉主通道和中央地标建立方向感。平台动态生成的细节包只填充预先定义的功能槽位，不能自行改路线；每格先检查投影、比例、伪字与碰撞能力，失败时回退到已准入素材。它只验证大面积布局、镜头、碰撞和制作阶段动态补景，不把试验场景提前写进故事；细节与失败素材见 [large-scene-review.md](large-scene-review.md)。

`?generated_room=1` 是“记忆真伪鉴定室”生成计时样本。通用墙、门和主角继续复用；深蓝鉴定地面、圆形残响扫描器、双样本比较器和腰高证物封存台全部由平台新生成。左右扫描、中央比较、右下封存的空间关系直接表达功能，不依赖说明牌把旧房间改名。`room_phase=shell` 使用深色程序网格、绿色语义体积和琥珀色 footprint 表示仍在形成；`room_phase=live` 从真实平台任务逐槽位替换正式素材。两种状态下主角、路线和碰撞都已可用；地图底部只说明“世界正在加载 / 可以先探索”，不显示任务、接口、碰撞或虚假百分比。刷新恢复和单件失败也不能移动物件、改变出口或阻塞其余房间。完整时间、真实回调与失败轮次见 [generated-room-benchmark.md](generated-room-benchmark.md)。
