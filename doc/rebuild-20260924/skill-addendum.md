
## 迁移复验：不得用表面存在代替能力验证（2026-09-24）

《记忆余量》复验暴露两类假阳性，适用于任何旧版本升级：

- **引擎**：package.json 含 RPGJS、地图成功加载、主角存在，不代表空间层已统一。审计每种可见地面、墙、家具和 NPC 的实际渲染归属；DOM/SVG 独立场景层要明确登记为迁移中。位置逐帧 setState 推动整个 React 场景重排也是独立性能风险。局部节流不能冒称完成空间层迁移。
- **自由对话**：存在输入框、有字符串返回、固定关键词命中，都不能证明自由对话通过。需要验证输入实际进入平台请求，收到真正响应后才离开等待阶段，网络失败保留草稿、退出取消并忽略迟到回复，不使用本地固定回答伪装成功。历史记录与剧情 reducer 的边界分别验证。mock 只证明 UI 生命周期；至少另存一次真实网络返回，且不得由一次成功宣称服务稳定。
- **步态**：同轮根图 edit 仍可能把 A/B 画成同一支撑相。“opposite leg” 提示词不是成功证据。把 A/B 放在同一中性底联系表中，检查屏幕左右脚的高低、近远腿和摆臂。复制姿态应拒绝或修正，不能切帧播放便宣称动画通过。屏幕坐标约束是候选修正方法，必须再验，不是保证。
- **语言**：中文协作不是产品默认中文。新旅程只对 zh 系统选择中文，其他语言回退英文；已有旅程语言与显式选择的优先级单独记录。至少用一个非中非英语系统环境验收。
