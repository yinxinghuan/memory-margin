
## RPGJS 迁移必须保留视觉行为（2026-09-24 第二轮实证）

《记忆余量》已把独立静态层和 NPC 接入 RPGJS 事件，四次真实出口往返读取到 15/17 个地图事件，场景 DOM 图层为零。以下是迁移额外门禁，不代表其旧门与墙素材已重新通过美术准入：

- **纹理存在不等于遮挡正确**：原 SVG 的南墙局部人物可见 mask、近侧门柱和前后门叶排序都必须列入迁移清单。静态烘焙不能把跟随人物的 mask 固化为空；实现应在 renderer 中更新小范围几何或 shader 参数，禁止逐帧重烘焙整墙。真实截图必须包括从南门进入时的脚点、人物上半身和离开遮挡区后的墙体恢复。
- **前景提示也会遮挡人物**：同位置的出口文字牌、交互点和底部行动文案不能重复叠加遮住人物。优先让底部行动按钮表达目的地；近距离人物提示保持在头顶外。需在出口刚进入的状态验收，不只看房间中央。
- **裁切工具可重复运行**：完整原始层与裁切后的运行纹理分目录保存。坐标始终从完整源 alpha 边界计算；禁止覆写源图后再次按其 bbox 裁切。旧格式必须在任何写入前明确拒绝，不能悄悄迁移并错位。保留 source/output、场景、深度与世界缩放元数据。
- **角色事实一致**：根图年龄/服装/单侧标记须与剧情、名字和肖像一致。同轮 edit 仍可能把侧向动作变成三分之四朝向；用本轮合格的侧向站姿约束修正可试，但必须记录父图改变并再次目检。只站立转向的 NPC 不得据此宣称四向步态都验证过。
- **性能证据边界**：持续输入按时间分段记录帧时间、场景事件和显示树节点数，同时做真实换房。桌面 Chrome 一分钟稳定只证明未观察到该环境下的持续退化，不证明 iPhone AlterU 已通过。运行时源变动后需要有针对性的复验。

待完善工具包能力：参数化静态层烘焙/事件工厂与前景可见性适配。项目已经有实现，但尚未完成包内独立装配验证，不能把项目脚本直接当作接收方已可用的通用工具。
